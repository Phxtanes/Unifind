# 📖 คำอธิบายการทำงานของโค้ด: `matchingService.js` (ระบบจับคู่ของหาย AI)

ไฟล์ `matchingService.js` ทำหน้าที่รันตรรกะเบื้องหลังในการจับคู่สิ่งของหาย (Lost Item) กับสิ่งของที่พบในคลัง (Found Item) แบบอัตโนมัติ โดยผสมผสานคิวรี่ฐานข้อมูลกับพลังของโมเดลภาษาระดับสูง (Gemini AI) ในการตรวจเช็ครายละเอียดภาษาธรรมชาติ

---

## 📦 1. ส่วนเริ่มต้นการเชื่อมต่อโมเดล AI (บรรทัด 1 - 49)

```javascript
22: const ai = new GoogleGenAI({ apiKey: process.env.GEMINI_API_KEY });
```
* **บรรทัด 22**: เริ่มต้นสร้างออบเจกต์สำหรับใช้งาน SDK ประมวลผลของ Gemini
```javascript
24: async function generateContentWithFallback(aiClient, options) { ... }
```
* **บรรทัด 24 - 49**: ระบบดักจับการตอบสนองที่ล้มเหลว (Resiliency) โดยจะทดลองรันคำสั่งเปรียบเทียบในรายชื่อโมเดล Gemini Flash ตั้งแต่รุ่นล่าสุดย้อนกลับไปหารุ่นเก่าทีละตัว หากตัวแรกติดขัดหรือล่ม เพื่อไม่ให้กระบวนการจับคู่หยุดชะงักลงกลางคัน

## 📑 2. ฟังก์ชันแปลรายละเอียดสิ่งของ (บรรทัด 50 - 95)

```javascript
50: function parseDescriptionText(desc) { ... }
```
* **บรรทัด 50 - 58**: ทำหน้าที่แยกวิเคราะห์ข้อมูลของที่ส่งมา เนื่องจากข้อมูลของหายอาจเซฟอยู่ในรูปแบบ String ทั่วไป หรือออบเจกต์ของ JSON (เช่น มีคีย์ย่อย `textDescription`) ฟังก์ชันนี้จะคัดกรองเฉพาะคำอธิบายเนื้อในแบบสตริงธรรมดาออกมาให้
```javascript
70: async function sendPushToLine(lineUserId, text) { ... }
```
* **บรรทัด 70 - 92**: ฟังก์ชันสำหรับใช้ **LINE Push API** เพื่อยิงข้อความแจ้งเตือนผลลัพธ์เข้าสู่สมาร์ทโฟนของนิสิตคนนั้นโดยตรงแบบเรียลไทม์

## 🔍 3. ตรรกะตรวจหาคู่เมื่อได้รับของใหม่เข้าคลัง (`checkFoundItemMatch`)

ฟังก์ชันนี้จะทำงานทันทีที่มี **เจ้าหน้าที่คลังเก็บของพบล่าสุดนำของมาชิ้นใหม่มาคีย์เข้าระบบ** หน้าที่ของระบบคือการสแกนหาตัวคนทำหายที่แจ้งความจำนงไว้ก่อนหน้านี้:

```javascript
96: exports.checkFoundItemMatch = async (foundItem) => {
```
* **ตรรกะการจับคู่ย่อย (Matching Engine Steps)**:
  1. ดึงข้อมูลรายการของหายทั้งหมด (`lost_items`) จาก Supabase ที่มีหมวดหมู่ (`category_id`) เดียวกันกับของพบล่าสุดนี้
  2. กรองข้อมูล Lost Items ที่มีค่าประวัติสถานะยังคงตามหาอยู่เท่านั้น (`status = 'searching'`)
  3. วนลูปจับคู่เพื่อคัดกรองเบื้องต้น หากสถานที่สูญหายหรือลักษณะของมีคีย์เวิร์ดตรงกัน
  4. สร้างชุด Prompt สำหรับส่งให้ AI วิเคราะห์ระดับลึก:
     ```javascript
     const prompt = `เปรียบเทียบของที่พบ ชิ้น A [ของเจอใหม่] กับของหาย ชิ้น B [ของแจ้งหายในระบบ] 
     ว่ามีโอกาสเป็นชิ้นเดียวกันหรือไม่ โดยดูจากลักษณะเด่น สี แบรนด์ และสถานที่...`;
     ```
  5. ยิงคำสั่งวิเคราะห์ไปยัง Gemini โดยผลลัพธ์ที่ตอบกลับจะต้องเป็น JSON ที่มีค่า `{ "match": true, "reason": "เหตุผลประกอบ" }` เท่านั้น
  6. หาก AI วิเคราะห์แล้วพบว่ามีความตรงกันจริง (Match):
     * ค้นหารหัส LINE User ID ของนิสิตผู้รายงานทำของหาย
     * ยิง Push Message ส่วนตัวแชทแจ้งความคืบหน้าทันทีเพื่อให้นำบัตรนิสิตเข้ามารับคืน

## 📝 4. ตรรกะตรวจหาคู่เมื่อนักศึกษาแจ้งทำของหายชิ้นใหม่ (`checkLostItemMatch`)

ฟังก์ชันนี้จะทำงานแบบขาสลับกัน คือ **เมื่อนักศึกษาพิมพ์คุยกับบอทเพื่อรายงานสิ่งของที่ตนทำตกหล่นไว้** ระบบจะวิ่งไปกวาดสายตาตรวจเช็คในห้องคลังเก็บสิ่งของส่วนกลางทันทีว่ามีผู้เก็บได้แล้วนำมาส่งมอบไว้ก่อนหน้านี้แล้วหรือยัง:

* **ตรรกะการทำงาน (Logic Flow)**:
  1. คิวรี่ฐานข้อมูลตารางสิ่งของในคลัง (`items`) กรองตามไอดีหมวดหมู่ที่ตรงกัน
  2. สกัดคำอธิบายและรูปภาพทั้งหมดที่คลังมีอยู่
  3. เรียกใช้งาน Gemini AI ประมวลผลเปรียบเทียบข้อความที่ผู้ใช้เพิ่งแจ้งเข้ามา กับลักษณะสิ่งของจริงที่เจ้าหน้าที่คลังลงทะเบียนเก็บรักษาไว้
  4. หากโมเดลวิเคราะห์ว่าพบของชิ้นที่มีลักษณะ สี และยี่ห้อ สอดคล้องกันจริง:
     * คืนค่ารายงานจับคู่และตอบกลับหาผู้ใช้ทันที เพื่อให้เดินทางไปตรวจสอบของด้วยตัวเอง ณ กองกิจการนักศึกษา
