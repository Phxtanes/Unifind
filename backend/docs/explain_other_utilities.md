# 📖 คำอธิบายการทำงานของโค้ด: โมดูลและสคริปต์สนับสนุน (Supporting Utilities)

ในบทนี้จะอธิบายโค้ดของไฟล์สนับสนุนทั้งหมดในฝั่งหลังบ้านของ Unifind ซึ่งทำหน้าที่ควบคุมสเตทอีเมล แคชข้อมูลออฟไลน์ และความจำแชท

---

## 📧 1. `emailService.js` (บริการส่งรหัส OTP ทางอีเมล)
ทำหน้าที่ประสานงานกับเครื่องเซิร์ฟเวอร์ส่งจดหมาย (SMTP) หรือพิมพ์รหัสลงหน้าจอสำหรับทดสอบ

* **การนำเข้าและเช็คสภาพแวดล้อม (Initialization)**:
  * นำเข้าโมดูล `nodemailer` สำหรับสื่อสารกับ SMTP Server
  * เช็คความสมบูรณ์ของตัวแปรสภาพแวดล้อม `SMTP_HOST`, `SMTP_USER`, และ `SMTP_PASS` หากระบุครบ จะสร้าง Transporter ในการเชื่อมต่อ หากไม่ครบจะพิมพ์ลงหน้าจอแชทสำหรับทดสอบแทน (Mock/Fallback)
* **ฟังก์ชัน `sendOtpEmail(email, otp)`**:
  * กำหนดข้อความหลัก `subject` เป็นภาษาอังกฤษกระชับเพื่อป้องกันฟิลเตอร์ตรวจจับสแปม
  * ออกแบบตัวโครงร่างจดหมายอีเมลด้วย HTML เพื่อความสวยงาม มีช่องแสดงตัวเลข OTP รหัส 6 หลักอย่างเด่นชัด
  * ตรวจเช็คหาก Transporter พร้อมใช้งาน จะส่งคำสั่งยิงอีเมลไปหาผู้รับปลายทางทันที หากไม่พร้อมหรือเกิดปัญหาเน็ตเวิร์ก จะวิ่งไปเรียกใช้ฟังก์ชัน `printOtpToConsole` พิมพ์ออกทางหน้าระบบควบคุมแทน

## ⏱️ 2. `otpStore.js` (ตัวจัดการสิทธิ์รหัส OTP ชั่วคราว)
ทำหน้าที่จดจำและเช็กความถูกต้องของรหัส OTP 6 หลักของนิสิตแต่ละคนในรูปของสเปซเวลาแบบจำกัด

* **ตรรกะการจัดเก็บ (In-memory Store)**:
  * สร้าง Map ชื่อ `pendingOtps` สำหรับบันทึกสถานะการยืนยันตัวตนคู่กับ `lineUserId`
* **ฟังก์ชัน `createPending(lineUserId, bindingData)`**:
  * ทำการสร้างรหัส OTP 6 หลักโดยการสุ่มตัวเลข `100000 - 999999`
  * เซฟรหัสนี้และข้อมูลอื่นๆ (บทบาท, อีเมล) ลงใน Map และบันทึกเวลาที่ส่งข้อมูล
* **ฟังก์ชัน `getPending(lineUserId)`**:
  * ดึงข้อมูล OTP ล่าสุดของผู้ใช้ออกมาตรวจสอบ
  * **จุดสำคัญ (Timeout logic)**: ตรวจสอบเวลาปัจจุบันเทียบกับเวลาที่สร้าง หากผ่านไปเกิน 5 นาที (`5 * 60 * 1000` มิลลิวินาที) ระบบจะลบค่า OTP นี้ทิ้งทันที และคืนค่าว่างกลับไปเพื่อปฏิเสธคำขอที่ล่าช้า

## 💬 3. `userSessionStore.js` (ความจำบทสนทนาของ LINE Bot)
ทำหน้าที่จดจำว่าผู้ใช้แชทแต่ละคนกำลังทำขั้นตอนอะไรค้างอยู่ เพื่อทำหน้าที่เป็นเครื่องบอกสถานะ (State Machine)

* **ตรรกะการทำงาน (Session Logic)**:
  * สร้าง Map เพื่อจำลองสถานะแชทคู่กับไอดี LINE ของผู้ใช้
* **ฟังก์ชัน `setState(lineUserId, state)`**:
  * เมื่อเรียกใช้ เช่น ตั้งค่าสถานะเป็น `AWAITING_REPORT_DETAILS` สำหรับผู้ที่แชทแจ้งของหายแต่ใส่ข้อมูลไม่ครบถ้วน
* **ฟังก์ชัน `getState(lineUserId)`**:
  * ดึงค่าสถานะปัจจุบันออกมาเพื่อตรวจสอบใน `lineRoutes.js` ว่าถัดไปควรตอบกลับผู้ใช้แบบไหน
* **ฟังก์ชัน `clearState(lineUserId)`**:
  * ล้างค่าสถานะทิ้งเมื่อดำเนินการส่งแบบคำร้องเสร็จสิ้น หรือผู้ใช้กดยกเลิกรายการ

## 🔄 4. `localDb.js` และ `dbSync.js` (แคชท้องถิ่นและตัวเชื่อมข้อมูลยามออฟไลน์)
ทำหน้าที่รักษาสถานภาพความต่อเนื่องของฐานข้อมูล ยามที่ระบบสูญเสียการเชื่อมต่อภายนอก

### A. `localDb.js`
* ทำหน้าที่เป็นส่วนกลางสำหรับการอ่านเขียนข้อมูลสำรองในรูปแบบไฟล์ JSON โค้ดจะคัดแยกฟังก์ชันเป็น:
  * `saveLocalLostItem(item)`: แปลงข้อมูลของหายที่เจ้าหน้าที่คีย์เข้าระบบให้เป็น JSON และเก็บสะสมต่อท้ายลงในไฟล์ `uploads/local_db.json`
  * `getLocalLostItems()` / `getLocalFoundItems()`: เปิดอ่านไฟล์ JSON และทำหน้าที่ดึงข้อมูลทั้งหมดไปส่งต่อให้ระบบวิเคราะห์ทดแทน Supabase

### B. `dbSync.js`
* ควบคุมจังหวะเวลาการตรวจสอบข้อมูลตกค้างผ่านคำสั่งวนซ้ำแบบตั้งเวลาล่วงหน้า (Cron Job/Interval):
  * รันฟังก์ชันตรวจสอบข้อมูลใหม่ทุกๆ 5 นาที
  * โค้ดจะอ่านแถวข้อมูลใน `local_db.json` ทีละตัว
  * พยายามส่งคำสั่งบันทึกไปยัง Supabase Cloud
  * หากการส่งข้อมูลสำเร็จ (คลาวด์รับทราบแล้ว) โค้ดจะลบแถวประวัติชิ้นดังกล่าวออกจาก `local_db.json` บนเครื่อง เพื่อป้องกันความซ้ำซ้อนของการซิงค์ในรอบถัดไป
