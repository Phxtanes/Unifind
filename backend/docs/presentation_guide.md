## 📸 1. ระบบสแกนรูปภาพและวิเคราะห์ด้วย AI (Image Vision Search)
หากกรรมการถามว่า: **"ตัวระบบตรวจจับคัดแยกประเภทและสกัดสีจากรูปภาพสิ่งของที่อัปโหลดอย่างไร?"**
* 📁 **ไฟล์ที่ต้องเปิด**: [backend/src/routes/lineRoutes.js](file:///c:/Users/ACER/Documents/GitHub/Unifind/backend/src/routes/lineRoutes.js)
* 🔍 **จุดสกัดในโค้ด**: ฟังก์ชัน `handleImageEvent`
* 💡 **คำอธิบายโค้ด**:
  1. ดึง Buffer ของไฟล์ภาพที่ส่งผ่านไลน์มาจากฟังก์ชัน `getLineImageBuffer`
  2. โหลดข้อมูลของหายทั้งหมดในตารางของระบบ (`supabase.from('items')`)
  3. ยิงส่งข้อมูลภาพ + รายการทั้งหมดเข้าโมเดล AI ในฟังก์ชัน `generateContentWithFallback` เพื่อจำแนกและจับคู่ความเหมือน
  4. ใช้คำสั่ง `replyToLine` แจ้งข้อความตอบรับให้ผู้ใช้ทราบทันทีเพื่อกันสกรีนห้องแชทเงียบ และยิงคำตอบจริงตามหลังทาง `pushToLine` (ระบบประมวลผลเสร็จสิ้น)

## 💬 2. ระบบคัดแยกความตั้งใจของผู้ใช้ (NLP Intent Routing)
หากกรรมการถามว่า: **"ระบบวิเคราะห์และคัดแยกข้อความที่ผู้ใช้พิมพ์เข้ามาอย่างไร?"**
* 📁 **ไฟล์ที่ต้องเปิด**: [backend/src/routes/lineRoutes.js](file:///c:/Users/ACER/Documents/GitHub/Unifind/backend/src/routes/lineRoutes.js)
* 🔍 **จุดสกัดในโค้ด**: ฟังก์ชัน `handleTextEvent`
* 💡 **คำอธิบายโค้ด**:
  * **ดักกรองด้วยโค้ดปกติ (Static Keyword - ไม่เสียเงินค่า API)**: บรรทัดแรกๆ จะทำการดักกรองคีย์เวิร์ดด่วนด้วย Regex เช่น คำว่า `"ผูกบัญชี"`, `"ยกเลิก"`, รหัส OTP 6 หลัก, หรือคำทักทายอย่าง `"สวัสดี"`
  * **ดักกรองด้วย AI (Dynamic NLP Router - ส่วนวิเคราะห์ความตั้งใจ)**: หากไม่ใช่คำสั่งเฉพาะ ระบบจะดักจับและส่งข้อความไปถาม Gemini AI ด้วยข้อคำสั่ง `classificationPrompt` เพื่อคัดแยกประเภทออกมาเป็น 4 หมวดหมู่หลัก ได้แก่ `SUMMARY` (ดูภาพรวม), `SEARCH` (สืบค้นเจาะจง), `REPORT_LOST` (แจ้งของหายใหม่), และ `CHITCHAT` (คุยทั่วไป)

## 🤖 3. ลอจิกการสืบค้นและส่งข้อความแจ้งเตือนคู่แมตช์ (Semantic Active Matching)
หากกรรมการถามว่า: **"ลอจิกการจับคู่ของหายและการส่งไลน์แจ้งเตือนผู้ใช้งานทำงานตรงไหน?"**
* 📁 **ไฟล์ที่ต้องเปิด**: [backend/src/services/matchingService.js](file:///c:/Users/ACER/Documents/GitHub/Unifind/backend/src/services/matchingService.js)
* 🔍 **จุดสกัดในโค้ด**: ฟังก์ชัน `runMatchingPipeline`
* 💡 **คำอธิบายโค้ด**:
  1. ระบบจะดึงรายการของที่ลงทะเบียนว่าหาย (`lost_items` สถานะ `searching`)
  2. ทำการคัดกรองเบื้องต้นจากสถานที่ประเภทเดียวกัน (`location_id`) หรือหมวดหมู่เดียวกัน (`category_id`)
  3. นำชื่อและรายละเอียดสิ่งของฝั่งผู้ทำหาย และฝั่งผู้เก็บได้ ส่งไปให้ Gemini AI ช่วยวิเคราะห์เปรียบเทียบเชิงลึก
  4. หากได้ผลลัพธ์ว่า **จับคู่ตรงกัน (Match)** ระบบจะสืบค้น LINE User ID ของเจ้าของผ่าน `lineBindings` และทำการเรียกส่งแจ้งเตือน **LINE Push Notification** ส่วนตัวทันที

## 🔄 4. ระบบหมุนเวียนกุญแจ AI สำรอง (API Key Rotation)
หากกรรมการถามว่า: **"ถ้าโควตา API คีย์ฟรีของ Google เต็ม 1,500 ครั้ง ระบบจะล่มหรือไม่ แก้ปัญหาอย่างไร?"**
* 📁 **ไฟล์ที่ต้องเปิด**: [backend/src/utils/aiHelper.js](file:///c:/Users/ACER/Documents/GitHub/Unifind/backend/src/utils/aiHelper.js)
* 🔍 **จุดสกัดในโค้ด**: ฟังก์ชัน `generateContentWithFallback` และ `rotateClient`
* 💡 **คำอธิบายโค้ด**:
  * ตัวแปร `apiKeys` จะทำการแยกคีย์ทั้งหมดในไฟล์ `.env` ที่คั่นด้วยเครื่องหมายจุลภาค `,` ออกมาเป็นอาเรย์
  * หากการเรียกใช้โมเดลคืนข้อผิดพลาด `429 (Resource Exhausted)` ฟังก์ชัน `rotateClient` จะถูกเรียกเพื่อขยับดัชนีไปใช้กุญแจตัวสำรองถัดไปทันที ทำให้ตอบแชทต่อได้โดยไม่ติดขัด
  * ฟังก์ชัน `getActiveClient` รองรับระบบ **Hot-Reload** ซึ่งจะดึงคีย์ใหม่จาก `.env` เข้ามาประมวลผลทันทีเมื่อเซฟไฟล์โดยไม่ต้องรีสตาร์ทตัวหลังบ้าน

## ⏱️ 5. ระบบป้องกันสแปมข้อความและการเคลียร์สถานะแชท (Rate Limiting & Anti-Stuck)
หากกรรมการถามว่า: **"มีระบบป้องกันผู้ใช้พิมพ์สแปมแชท หรือมีระบบจัดการเพื่อไม่ให้บทสนทนาค้างได้อย่างไร?"**
* 📁 **ไฟล์ที่ต้องเปิด**: 
  1. [backend/src/utils/rateLimiter.js](file:///c:/Users/ACER/Documents/GitHub/Unifind/backend/src/utils/rateLimiter.js) (ตัวนับสแปมรายคน)
  2. [backend/src/routes/lineRoutes.js](file:///c:/Users/ACER/Documents/GitHub/Unifind/backend/src/routes/lineRoutes.js) (ตัวสกัดกั้นสัญญาณ Webhook และ Try-Catch สเตทสนทนาค้าง)
* 🔍 **จุดสกัดในโค้ด**:
  * ฟังก์ชัน `isRateLimited` ใน `rateLimiter.js`
  * บล็อก Try-Catch-Finally ครอบคลุมการทำงานส่งของหายใน `lineRoutes.js`
* 💡 **คำอธิบายโค้ด**:
  * **ป้องกันสแปม**: ตรวจจับความถี่ของ LINE User ID หากส่งข้อความเกิน 6 ครั้งต่อนาที ระบบจะรีบยิงคำเตือนและทำการ Bypass ปฏิเสธการเรียกประมวลผลทันที
  * **ป้องกันหน้าแชทค้าง**: สเตทสนทนาค้างจะถูกล้างทิ้งผ่านบล็อกคำสั่ง `finally { userSessionStore.clearState(lineUserId) }` ทันทีแม้ว่า API AI จะล้มเหลว ทำให้ผู้ใช้สามารถพิมพ์พูดคุยต่อได้ปกติโดยไม่ต้องสยบติดอยู่ที่หน้าจอแจ้งขัดข้องเดิม
