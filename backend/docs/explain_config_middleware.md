# 📖 คำอธิบายการทำงานของโค้ด: การตั้งค่า (Configs) และ มิดเดิลแวร์ (Middlewares)

ส่วนประกอบเหล่านี้ทำหน้าที่เป็นชั้นคัดกรองความปลอดภัย (Security Check), ตัวกลางสกัดภาพอัปโหลด (File Stream), และตัวบันทึกข้อมูลย่อยลงระบบไฟล์ของโฮสต์

---

## 🔒 1. `authMiddleware.js` (มิดเดิลแวร์ตรวจสอบความปลอดภัยของการเข้าถึง)
ทำหน้าที่ดักตรวจ HTTP Request ทุกรายการที่จะเข้ามาติดต่อกับ API หน้าบ้าน เพื่อคัดกรองสิทธิ์ผู้ใช้งาน

* **`verifyToken` (ฟังก์ชันแกะและตรวจสลากความถูกต้องของ JWT)**:
  * ดึงค่าโทเค็นจาก Header ในฟิลด์ `Authorization` (คาดหวังโครงสร้างแบบ `Bearer [token_string]`)
  * **ระบบจำลองสำหรับการพัฒนา (Bypass Token)**:
    * ระบบมีฟีเจอร์ช่วยให้ทีมงานเดฟรันโปรแกรมทดสอบได้ลื่นไหล หาก Token ที่ส่งมาเท่ากับ `"bypass-token-12345"` หรือ `"mock-token"` -> ระบบจะข้ามขั้นตอนไปอนุมัติสิทธิ์เป็น Admin ทันทีโดยไม่ต้องแกะ JWT
  * **ระบบแกะรหัสจริง**: หากไม่ใช่ Token ทดสอบ จะนำโทเค็นไปเช็คกับกุญแจความปลอดภัย `process.env.JWT_SECRET` ผ่านเมธอด `jwt.verify` 
    * หากไม่ถูกต้องหรือหมดอายุ: ส่งรหัสเตือนภัย 401 (Unauthorized)
    * หากถูกต้อง: จะอ่านเอา ID ผู้ใช้งาน และระดับสิทธิ์ (Role) บันทึกลงในออบเจกต์คำขอ `req.userId` และ `req.userRole` เพื่อส่งต่อไปยังขั้นตอนถัดไปใน Controller
* **`isAdmin`**: ตรวจเช็คค่า `req.userRole` หากระดับสิทธิ์ไม่ใช่แอดมินระดับสูงสุด จะส่งรหัสข้อผิดพลาด 403 ปฏิเสธการเข้าใช้งาน
* **`isStaffOrAdmin`**: คัดกรองคล้ายกับแอดมิน แต่อนุญาตให้เจ้าหน้าที่ระดับปฏิบัติการ (`staff`) เข้าถึงฟังก์ชันการทำรายการคืนของหรือสืบค้นของได้

## 📷 2. `uploadMiddleware.js` (มิดเดิลแวร์คัดกรองรูปภาพอัปโหลด)
ทำหน้าที่สกัดกั้นและตรวจสอบประเภทไฟล์ภาพถ่ายสิ่งของสูญหาย ก่อนที่ระบบจะอนุญาตให้เซฟไฟล์ลงระบบคลัง

* **การใช้ไลบรารี `multer`**:
  * ใช้คำสั่ง `multer.memoryStorage()` เพื่อบอกโปรแกรมว่า ให้นำไฟล์ที่อัปโหลดขึ้นมาบันทึกพักไว้บนหน่วยความจำชั่วคราว (Buffer RAM) ก่อน เพื่อความรวดเร็วในการประมวลผลแทนการเขียนไฟล์ขยะลงบนฮาร์ดดิสก์เครื่องโดยตรงทันที
* **การตั้งค่าจำกัดไฟล์ (File Constraints)**:
  * `fileSize: 10 * 1024 * 1024` คัดกรองขนาดไฟล์ภาพห้ามใหญ่เกิน 10MB เพื่อป้องกันการยิงสแปมไฟล์ทำให้พื้นที่เซิร์ฟเวอร์เต็ม
  * **ระบบการตรวจสอบประเภทไฟล์ (File Filter)**:
    * ใช้คำสั่งตรวจสอบว่านามสกุลประเภทไฟล์ (`file.mimetype`) ต้องเริ่มต้นคำว่า `"image/"` เท่านั้น (เช่น image/png, image/jpeg)
    * หากผู้ใช้งานส่งไฟล์ประเภทอื่นที่ไม่ถูกต้องเข้ามา (เช่น ไฟล์ PDF หรือโปรแกรม EXE) ระบบจะบล็อกและโยน Error คำเตือนปฏิเสธการลงทะเบียนของกลับไปหน้าเว็บแอปพลิเคชันทันที

## 📑 3. `claimsDb.js` (ฐานข้อมูลจำลองสำหรับคำร้องขอของคืน)
ทำหน้าที่รวบรวมประวัติความเคลื่อนไหวของการเคลมของตกหล่น

* **`loadClaims` / `saveClaims`**:
  * ทำหน้าที่เปิดไฟล์ `uploads/claims.json` และเขียนกลับข้อมูลใหม่ลงฮาร์ดดิสก์
* **`createClaim` (ลงทะเบียนคำร้องแผงเคลมตัวใหม่)**:
  * คำนวณหา Auto-increment ID แบบแมนนวล โดยเช็กจากค่าเลข ID สูงสุดที่พบล่าสุดในอาร์เรย์ (`Math.max`) บวกเพิ่มขึ้นทีละ 1
  * กำหนดสถานะเริ่มต้นของเอกสารใบเคลมให้เป็นสีส้มรอการพิจารณา (`status: 'pending'`)
* **`rejectOtherPendingClaims` (ยกเลิกคำขอทับซ้อน)**:
  * ค้นหาคำร้องของของชิ้นเดียวกันนี้ของผู้ยื่นรายอื่นๆ ที่ค้างอยู่ และเซตค่าสถานะเป็น `'rejected'` ทั้งแผงทันทีหลังจากชิ้นหลักได้รับความเห็นชอบ

## 🔗 4. `lineBindings.js` (โมดูลบันทึกคู่ความสัมพันธ์ LINE OA & User Account)
ทำหน้าที่จับคู่สะพานตัวตนระหว่างโลกภายนอก (แอป LINE) และหลังบ้าน (ระบบอีเมล)

* **ความสำคัญในแง่ซอฟต์แวร์**: 
  * ระบบจัดเก็บเป็น Key-Value JSON บนไฟล์โลคอล `uploads/line_bindings.json`
  * เมื่อคีย์คำสั่งจับคู่ `bind(email, lineUserId)` ระบบจะใช้ค่า **อีเมลพิมพ์เล็กเป็นดัชนีคีย์หลัก** (แปลงตัวอักษรเป็นพิมพ์เล็กทั้งหมดด้วย `.toLowerCase().trim()`) เพื่อป้องกันปัญหาพยัญชนะตัวใหญ่ตัวเล็กไม่ตรงกันในการตรวจสอบประวัติ
  * มีเมธอดการดึงสองทิศทาง: `getLineUserId(email)` (ดึงหาไอดี LINE จากอีเมล) และ `getEmailByLineUserId(lineUserId)` (แกะหาอีเมลปลายทางจากไอดี LINE เพื่อเช็กสิทธิ์)
