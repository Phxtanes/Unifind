# 📖 คำอธิบายการทำงานของโค้ด: ฝั่งตัวควบคุม (Controllers)

ในโครงสร้าง MVC (Model-View-Controller) ตัว **Controller** ทำหน้าที่เป็นสะพานรับ HTTP Request จากบราวเซอร์หรือเว็บแอปพลิเคชันฝั่งเจ้าหน้าที่ ดึง/บันทึกข้อมูลกับฐานข้อมูล และส่งข้อมูลกลับไปหาฝั่งแสดงผล

---

## 🔐 1. `authController.js` (การสมัครสมาชิกและการเข้าสู่ระบบ)
ทำหน้าที่ดูแลการเข้าใช้งานระบบของเจ้าหน้าที่ (Staff) และแอดมิน (Admin)

* **`register` (สมัครสมาชิกเจ้าหน้าที่)**:
  * รับค่า `username`, `email`, `password`, `full_name` จากแบบฟอร์ม
  * เช็กกับตาราง `users` ใน Supabase ว่า username หรือ email เคยสมัครไปแล้วหรือยัง
  * หากยังไม่เคยสมัคร จะนำรหัสผ่านเข้าโมเดลแฮช `bcrypt.hash(password, 8)` เพื่อเข้ารหัสความปลอดภัย ป้องกันรหัสผ่านรั่วไหล
  * บันทึกข้อมูลลงฐานข้อมูลโดยกำหนดบทบาทเริ่มต้นเป็น `'STAFF'` และตั้งสถานะเริ่มต้นเป็น `'Inactive'` เพื่อรอแอดมินอนุมัติสิทธิ์ใช้งาน (กรรมการจะชอบตรงที่ระบบมีการป้องกันความปลอดภัยไม่ให้พนักงานเข้ามาดูข้อมูลพละการ)
* **`login` (เข้าสู่ระบบ)**:
  * ตรวจเช็คข้อมูลไอดีผู้ใช้
  * ดักจับสถานะ: หากสถานะบัญชีเป็น `'Inactive'` (รออนุมัติ) หรือ `'Suspended'` (ถูกระงับสิทธิ์) จะตอบกลับรหัสความปลอดภัย 403 ปฏิเสธการเข้าสู่ระบบ
  * ตรวจสอบความถูกต้องของรหัสผ่านแฮชผ่านคำสั่ง `bcrypt.compare`
  * เมื่อถูกต้องจะสร้างรหัสสัญญาณอนุญาตการเชื่อมต่อ **JWT (JSON Web Token)** ผ่าน `jwt.sign` โดยส่งสิทธิ์และไอดีเก็บไว้ในโทเค็น (Token) และมีระยะเวลาหมดอายุ
* **`approveUser` / `rejectUser` / `deactivateUser`**:
  * เป็นฟังก์ชันที่อนุญาตให้เฉพาะสิทธิ์ผู้ดูแลระบบสูงสุด (Admin) เข้าถึง เพื่อทำการเปลี่ยนสถานะบัญชีเจ้าหน้าที่ให้เป็น `Active` หรือลบคำขอทิ้งกรณีปฏิเสธ

## 📦 2. `itemController.js` (ตัวจัดการคลังสิ่งของที่พบล่าสุด)
ทำหน้าที่ควบคุมคำสั่งข้อมูลสิ่งของคงคลัง (`items`) ที่เจ้าหน้าที่คลังเก็บของของหายเป็นผู้ลงทะเบียนและจัดการสถานะการคืนของ

* **`createItem` (ลงทะเบียนของที่พบล่าสุดชิ้นใหม่)**:
  * รับรายละเอียดของที่พบ หมวดหมู่ วันเวลา และสถานที่
  * ตรวจสอบความสมบูรณ์และเพิ่มแถวข้อมูลสิ่งของตัวล่าสุดลงบนฐานข้อมูล Supabase
  * **จุดต่อยอดสำคัญ**: เรียกเมธอด `matchingService.checkFoundItemMatch` ทันทีหลังจากแอดข้อมูลเสร็จ เพื่อสั่งรันปัญญาประดิษฐ์ AI จับคู่สแกนหาผู้รายงานทำของหาย หากพบตัว จะส่งการแจ้งเตือนทาง LINE ส่วนตัวโดยอัตโนมัติ
* **`claimItem` (การกดยื่นคำร้องของนักศึกษาใน LINE OA)**:
  * เมื่อนักศึกษาทำรายการกดยื่นขอเคลมของคืนผ่าน LINE ระบบจะสร้างข้อมูลการยื่นขอเคลมของลงไฟล์แคช `claims.json` ผ่านฟังก์ชัน `claimsDb.createClaim`
* **`approveClaim` (อนุมัติคืนของให้เจ้าของ)**:
  * เมื่อเจ้าหน้าที่ตรวจสอบหลักฐานในหน้าเว็บแล้วคลิกปุ่มอนุมัติ:
    * ระบบจะอัปเดตสถานะของเคลมชิ้นนั้นให้เป็น `'approved'`
    * เปลี่ยนสถานะของของชิ้นนั้นในคลัง Supabase เป็น `'returned'` และบันทึกประวัติชื่อผู้มารับคืน
    * **ตรรกะตัดแคนดิเดตอัตโนมัติ (`rejectOtherPendingClaims`)**: ระบบจะสแกนหาแถวคำร้องการขอเคลมของชิ้นนี้จากนักศึกษาคนอื่นๆ ที่ยังค้างสถานะรอตรวจสอบ (`pending`) และเปลี่ยนสถานะให้กลายเป็นถูกปฏิเสธ (`rejected`) ทั้งหมดทันทีพร้อมบอกเหตุผลว่ามีผู้อื่นนำหลักฐานมารับของคืนไปเรียบร้อยแล้ว เพื่อปิดคิวงานเจ้าหน้าที่อย่างชาญฉลาด

## 📝 3. `lostItemController.js` (ตัวจัดการรายงานของสูญหายของนิสิต)
ทำหน้าที่รักษาสถานะสิ่งของที่นิสิตลงทะเบียนแจ้งทำของหายไว้ (`lost_items`)

* **`createLostItem` (เพิ่มรายการของหายชิ้นใหม่)**:
  * รับข้อมูลประเภทและสถานที่ทำหาย บันทึกข้อมูลแถวลงบน Supabase Cloud
  * ทริกเกอร์ระบบเช็กคู่จับคู่ประชากรของแอร์เรีย (`matchingService.checkLostItemMatch`) เพื่อเปรียบเทียบในคลังของที่เจอทันที
* **`updateStatus` (การอัปเดตความเคลื่อนไหว)**:
  * อนุญาตให้เจ้าหน้าที่หรือนักศึกษาเปลี่ยนสเตตัสการตามหา เช่น เปลี่ยนจาก `'searching'` (กำลังตามหา) เป็น `'resolved'` (พบเรียบร้อยแล้ว) หรือ `'cancelled'` (ยกเลิกรายการ)

## 👤 4. `personController.js` (ระบบแมปประชากรและ LINE ID)
ทำหน้าที่ประสานงานข้อมูลระบุตัวตนบุคคลภายนอกและภายในโครงการ

* **`getAllPersons`**:
  * ดึงรายละเอียดรายชื่อนักศึกษาและบุคลากรเพื่อแสดงตารางรายงานบนหน้าแดชบอร์ด
* **`getBindingStatus`**:
  * ใช้สำหรับตรวจสอบประวัติว่านักศึกษาคนนี้ผูกบัญชีใช้งานกับ LINE ID ตัวใดอยู่ เพื่อช่วยเจ้าหน้าที่ในการระบุตัวตนและตรวจสอบสถิติเชิงปริมาณของผู้ลงทะเบียนเข้าใช้งานในองค์กร
